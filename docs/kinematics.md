# r1.kinematics: 팔 FK / IK

`r1/kinematics/arm_ik.py` 의 `ArmIK` 는 pinocchio 로 R1 팔의 손 끝 위치를 계산(FK)하고, 목표 위치로 보내는 관절각(IK)을 구합니다.

| 파일 | 내용 |
|---|---|
| `arm_ik.py` | `ArmIK`: `fk`, `fk_pose`, `solve`, `gravity_torque` |
| `motion.py` | `CartesianArm.move_to()`: 손 끝 직선 이동 (IK + 양팔·허리 중력 보상 + 속도 피드포워드) |
| `examples/reach_line.py` | 왼손 끝을 몸 앞에서 직선 왕복, 실제 손 끝 오차 측정 |
| `examples/push_box.py` | 상자를 목표 영역까지 미는 데모 (Python 시뮬 기본 장면용) |

## 사용법

```python
from r1.kinematics.arm_ik import ArmIK
ik = ArmIK()                                    # third_party/unitree_ros/.../R1.urdf
p = ik.fk(q29, "left")                          # 손 끝 위치 (pelvis 기준) [m]
q29_new, ok, err = ik.solve([0.30, 0.20, 0.05], q29, "left")
tau = ik.gravity_torque(q29, ik.arm_motors("left"))   # 팔 중력 보상 토크 (29칸)
```

```bash
bash sim/run_r1_sim.sh                          # 터미널 1
source env/setup_sim.sh                         # 터미널 2
python -m r1.kinematics.examples.reach_line
```

## 정의

- **좌표계**: 골반(`pelvis_link`) 기준. x 앞, y 왼쪽, z 위. 골반은 고정(매달린 상태)으로 본다.
- **손 끝**: `wrist_roll_link` 에서 x 방향 0.10 m (주먹 중심). 손 메시는 x 방향으로 0 ~ 0.143 m.
- **IK**: 위치만 맞춤(3D). 5자유도 팔이라 자세까지 맞출 수 없다. 지정한 팔 관절(5개)만 움직이고 허리 등 나머지는 입력값 유지.
- **알고리즘**: 감쇠 최소제곱(DLS), 반복당 관절 변화 최대 0.2 rad, 관절 범위 0.05 rad 안쪽으로 클램프.
  실패하면 무작위 시작 자세로 최대 8번 재시도. 닿지 않는 목표면 가장 가까웠던 자세와 `ok=False` 를 돌려준다.
- 입출력은 `r1.interface` 와 같은 29칸 배열.

## 검증 결과 (2026-10-18)

| 항목 | 결과 |
|---|---|
| FK: pinocchio(URDF) vs MuJoCo(MJCF), 무작위 자세 50개 × 양팔 | 최대 차이 **0.000 mm** (두 모델의 기구학이 동일) |
| IK: 도달 가능한 무작위 목표 200개 | **200/200 성공**, 최대 오차 1.0 mm, 평균 2.4 ms/회 |
| IK: 닿지 않는 목표 (0.8, 0.2, 0.0) | `ok=False`, 가장 가까운 점 (0.44, 0.17, 0.12) 반환 |

## 작업 영역 (왼손, 기본 자세에서 IK, 0.05 m 격자)

| 높이 z (골반 기준) | 도달 x (앞) | 도달 y (왼쪽) |
|---|---|---|
| +0.10 m | 0.10 ~ 0.40 m | -0.10 ~ 0.40 m |
|  0.00 m | 0.10 ~ 0.35 m | -0.10 ~ 0.40 m |
| -0.10 m | 0.10 ~ 0.25 m | -0.05 ~ 0.35 m |
| -0.20 m | 닿지 않음 | |

- R1 은 팔이 짧고 허리 pitch(앞으로 숙이기)가 없다.
- **조작 장면 설계 기준**: 테이블 윗면은 골반 높이 근처(골반 기준 z ≈ -0.05, 바닥 기준 약 0.7 m), 물체는 몸 앞 x = 0.20 ~ 0.35 m.
- 오른손은 y 부호가 반대인 대칭 영역.

## 손 끝 추종 오차 분석 (시뮬, 고무줄, 직선 왕복 0.25 m / 4 s)

| 조건 | 정지 오차 | 이동 중 평균 | 이동 중 최대 |
|---|---|---|---|
| PD 만 | 34.0 mm | 34.1 mm | 43.0 mm |
| + 중력 보상 | **3.0 mm** | 23.7 mm | 43.1 mm |
| + 중력 보상 + 속도 피드포워드 | 3.0 mm | 20.2 mm | 34.1 mm |

- 정지 오차의 원인은 **중력 처짐**이었다 → `gravity_torque` 로 해결.
- 이동 중 오차는 거의 전부 **시간 지연**이다. 측정값을 약 160 ms 앞당겨 비교하면 오차 3.4 mm, 오차도 이동 방향(y)에만 있다.
- 지연의 원인 조사:
  - 제어 스레드 주기: 평균 2.2 ms (정상). 속도 제한(1 rad/s)에도 걸리지 않음 (필요 최대 0.76 rad/s).
  - 팔꿈치 계단 응답: 오프라인 MuJoCo(시뮬 시간) 48 ms vs C++ 시뮬(실제 시간) 215 ms. kp 를 5배로 올려도 C++ 시뮬은 거의 그대로.
  - 중력 낙하 시간: 오프라인 182 ms vs C++ 시뮬 310 ms → **C++ 시뮬이 실시간보다 약 1.7배 느리게 돈다**.
  - 측정 당시 다른 시뮬·RViz·`lowstate_bridge`(CPU 96%)가 함께 돌고 있었다.
- 결론: IK·FK·중력 보상은 정확하다. 지연은 C++ 시뮬의 실시간 미달이 주원인이었다.

### Python 시뮬에서 재측정 ([sim.md](sim.md))

| 조건 | 정지 | 이동 중 평균 | 이동 중 최대 |
|---|---|---|---|
| 팔만 중력 보상 | 16.6 mm | 8.6 mm | 17.7 mm |
| **양팔 + 허리 중력 보상** | **0.4 mm** | **4.0 mm** | **10.6 mm** |

- Python 시뮬(RTF 1.00)에서 이동 중 오차가 20 → 8.6 mm 로 줄어 C++ 시뮬 속도가 원인이었음을 확인.
- 남은 정지 오차는 **허리 처짐**: 팔 무게로 허리 roll 이 0.052 rad 처져 손 끝이 16 mm 밀렸다. 허리까지 보상하면 0.4 mm ([decisions.md](decisions.md) D13).
  (C++ 시뮬의 고무줄 상태에서는 몸 전체가 매달려 이 효과가 덜 드러났던 것으로 보인다.)

## 상자 밀기 (push_box)

- 높이: 손을 내리면 주먹이 아래로 기울어 앞쪽 아랫부분이 먼저 테이블에 닿는다. 손 끝 z = 테이블 + 0.04 에서는 접촉,
  **+0.055 에서 경로 전체 최소 여유 17 mm** (`mj_geomDistance` 로 확인).
- 결과: 상자 (0.27, 0.22) → (0.253, 0.008), 목표 (0.27, 0.00) 까지 1.9 cm. 단계별 손 끝 오차 0.5 / 0.7 / 6.8 / 5.1 mm.
