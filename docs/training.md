# 모방학습 한 바퀴: 자동 시연 → ACT 학습 → 시뮬 평가

로봇 도착 전에 **데이터 수집 → 학습 → 실행** 전체 흐름을 시뮬에서 끝까지 돌려 본 기록입니다.
서버를 쓸 수 없어 학습도 로컬 GTX 1060 (6 GB) 에서 했습니다.

## 1. 데이터: 자동 시연 (`r1.teleop.auto_push`)

시뮬의 상자 위치를 보고 스크립트가 상자를 미는 시연. 키보드 시연과 **같은 경로**(DDS 제어 + ROS2 카메라 + `EpisodeRecorder`)로 기록한다.

```bash
python -m r1.sim.run --headless --ros --cam-hz 30 --cam-size 320x240 --seed 42     # 터미널 1
python -m r1.teleop.auto_push --episodes 50 --seed 42                              # 터미널 2
```

- 전문가 동작: 준비 위치 → 상자 왼쪽 위 → 내리기 → 오른쪽으로 밀기 → 들기
- 에피소드마다 무작위: 정렬 x ±0.8 cm, 접근 여유 1~3 cm, 밀기 높이 +0~0.8 cm, 끝 위치 ±1 cm, 속도 0.07~0.11 m/s, 시작 전 멈춤 0.2~0.6 s
- 성공한 에피소드만 저장 (상자-목표 거리 < 0.04 m)

| 항목 | 결과 (2026-10-18) |
|---|---|
| 데이터셋 | `data/datasets/r1_push_box_auto` (36 MB) |
| 에피소드 | 50 저장 / 53 시도 (실패 3 버림) |
| 프레임 | 8,257 (에피소드당 131~205, 평균 5.5 s) |
| 상자-목표 거리 | 평균 2.0 cm, 최대 4.0 cm |
| 수집 시간 | 약 13 분, 시뮬 RTF 1.00 유지 |

## 2. 기준선: 눈 감고 재생 (`r1.policy_runner.blind_replay`)

시연 1개(에피소드 0)의 관절 명령을 **상자 위치와 무관하게** 그대로 재생한다. 카메라를 보지 않는다.
학습된 정책이 이보다 높아야 "카메라로 상자를 보고 행동을 바꾼다"고 말할 수 있다.

```bash
python -m r1.sim.run --headless --ros --cam-hz 30 --cam-size 320x240 --seed 123   # 평가용 시드 고정
python -m r1.policy_runner.blind_replay --episodes 30 --log data/eval/blind_seed123.jsonl
```

예비 시험 (12 에피소드, 시드 123): **8/12 = 67 %**. 실패 유형:
- 상자가 왼쪽 끝(y ≥ 0.24)일 때 손이 상자 **위로** 내려와 밀지 못함 (거리 15 cm)
- 상자가 앞뒤로 치우쳤을 때(x ≈ 0.25) 목표에서 벗어남 (거리 4.5 ~ 5 cm)

**정식 측정 (30 에피소드, 시드 123): 13/30 = 43 %** (`data/eval/blind_seed123.jsonl`). 실패 17 회:
- 상자 y ≥ 0.23 (9 회): 손이 상자 위로 내려와 밀지 못함, 거리 10 ~ 16 cm
- 상자 x ≤ 0.258 (8 회): 밀었지만 목표에서 4.5 ~ 8 cm 벗어남

→ 상자 위치를 봐야 성공하는 경우가 절반 이상이다. 학습과 동시에 돌렸지만 시뮬 RTF 1.00 유지.

## 3. ACT 학습 (`training/il/train_act.sh`)

```bash
source env/setup_sim.sh
bash training/il/train_act.sh                                    # 기본: r1_push_box_auto, 20k steps
DATASET=r1_push_box STEPS=50000 BATCH=16 bash training/il/train_act.sh   # 다른 설정 (서버 등)
```

| 설정 | 값 | 이유 |
|---|---|---|
| 정책 | ACT (ResNet18 ImageNet 사전학습, Transformer, CVAE) | LeRobot 기본, 적은 데이터에 강함 |
| chunk_size | 30 (1 s @ 30 fps) | 에피소드가 5.5 s 로 짧아 기본 100 (3.3 s) 은 길다 |
| n_action_steps | 학습 10 → **실행 30 으로 변경** | 10 이면 출발하지 못함 (6절). 실행 때 `--n-action-steps 30` 으로 덮어씀 |
| batch / lr | 8 / 1e-5 | 1060 6 GB, ACT 기본 lr |
| steps | 20,000 (약 19 epoch) | |
| 그 밖 | ACT 기본값 (dim_model 512, enc 4 / dec 1 층, kl_weight 10) | |

- 모델 5,156 만 파라미터. 1060 에서 **0.15 s / step** (초당 6.5 step) → 20k step 약 50 분.
- 체크포인트: `data/checkpoints/<RUN>/checkpoints/{005000,...,last}/pretrained_model`

## 4. 평가 (`r1.policy_runner.run_act`)

```bash
python -m r1.sim.run --headless --ros --cam-hz 30 --cam-size 320x240 --seed 123
python -m r1.policy_runner.run_act --ckpt data/checkpoints/<RUN>/checkpoints/last/pretrained_model \
    --episodes 30 --log data/eval/act_seed123.jsonl
```

- 에피소드: 리셋(상자 무작위) → 준비 위치 → 정책 8 s 실행 → 상자-목표 거리 < 0.04 m 면 성공
- 정책 출력(왼팔 관절 5)에도 중력 보상·속도 피드포워드·관절 범위·속도 제한이 그대로 적용된다
- 같은 시드(123)로 기준선과 같은 상자 위치 순서에서 비교한다

| 방법 | 성공률 (30 에피소드, 시드 123) |
|---|---|
| 기준선: 눈 감고 재생 | **13/30 = 43 %** |
| ACT 5k step | **3/30 = 10 %** (기준선보다 낮음, 아래 5절) |
| **ACT 40k + 파인튜닝 10k (v3, n30)** | **30/30 = 100 %** — 7절 |
| ACT 20k step | **6/30 = 20 %** — 실패 24 중 22 회는 출발 못 함. 성공 6 중 5 회는 기준선이 실패한 상자 위치 |
| ACT 20k step, v2 데이터 (시작 정지 없음) | 1/30 = 3 % (⚠ 학습과 동시에 뷰어로 평가해 RTF 0.65~0.89 — 공정 비교 아님) |
| **ACT 20k, n_action_steps 30, v1 데이터** | **25/30 = 83 %** (평균 거리 2.3 cm) |
| **ACT 20k, n_action_steps 30, v2 데이터** | **25/30 = 83 %** (평균 거리 2.5 cm) |
| ACT 30k, n_action_steps 30, v2 **100 개** | 25/30 = 83 % — 실패 에피소드까지 50 개·20k 와 동일 |
| **ACT 40k, n_action_steps 30, v2 100 개** | **27/30 = 90 %** (평균 거리 2.5 cm, RTF 0.97~1.00, 뷰어 켬) |

- 기준선 성공 13 회는 ACT 도 모두 성공, 기준선 실패 17 회 중 12 회를 ACT 가 추가로 성공 → **카메라로 상자 위치를 보고 행동한다.**
- 남은 실패 5 회는 두 정책이 같은 에피소드: 상자 x ≤ 0.25 (앞쪽), 목표까지 4.0 ~ 5.0 cm 로 반지름(4 cm)을 조금 벗어남.
  자동 시연이 y 방향으로만 밀고 x 를 보정하지 않으므로 **시연의 한계를 물려받은 것**. 개선: 시연이 대각선으로 밀어 x 를 맞추게.
- v1 / v2 차이 없음 → '시작 정지' 는 원인이 아니었다.
- 데이터 100 개·30k 도 **같은 5 에피소드에서 실패** → 학습량이 아니라 시연의 한계. 40k 에서 20, 22 번(원래 4.3 cm, 경계선)이
  반지름 안으로 들어와 90 % 가 되었지만, 경계선의 작은 변화일 수 있다. 남은 실패 3 회도 상자 x ≤ 0.248.
- 다음: 시연 스크립트가 상자 x 에 맞춰 대각선으로 밀어 x 를 보정하게 개선 → 같은 조건으로 비교.

## 5. 문제: 정책이 준비 자세에서 출발하지 못함

**증상** (5k step): 실패 27 회 대부분에서 상자가 전혀 움직이지 않았다 (최종 거리 = 시작 거리).
손 끝을 0.5 s 마다 찍어 보니 6 s 내내 준비 위치 (0.24, 0.33, 0.08) 근처에서 맴돌았다.

**원인 (가설)**: 자동 시연이 **시작 전 0.2 ~ 0.6 s 동안 정지**한 뒤 출발한다. 언제 출발할지 알려 주는 단서가 관측(영상, 관절)에 없어서,
정책이 "준비 자세 = 계속 정지" 를 배웠다. 모방학습에서 흔한 문제 (정지 구간·시간 의존 행동이 관측으로 설명되지 않음).
200 step 정책이 성공한 것은 덜 학습되어 상태를 무시하고 평균 쓸기 동작을 냈기 때문으로 보인다.

**대응 후보**
1. 데이터: 시작 전 정지 제거, 끝 정지 축소 → 다시 수집·학습
2. ACT: 예측한 묶음을 끝까지 실행(`n_action_steps = chunk_size`) 해 한 번 출발하면 멈추지 않게
3. 더 학습 (20k 결과로 확인)

**20k 결과**: 10 % → 20 % 로 늘었지만 실패 24 회 중 22 회는 여전히 상자를 건드리지 못했다 (출발 못 함).
반면 **출발한 경우는 상자 위치에 맞춰 밀었다**: 성공 6 회 중 5 회가 기준선(같은 동작 반복)이 실패한 상자 위치(x ≤ 0.254)였다.
→ 정책은 카메라를 쓰고 있고, 남은 문제는 출발. 대응 1(데이터)을 **같은 학습 설정**으로 시험한다 (원인을 하나만 바꿔 확인).

v2 데이터: `data/datasets/r1_push_box_auto_v2` — 시작 전 정지 0 (`--max-start-pause 0`, 기본값), 시드 43, 50 / 53 시도.

## 6. 진짜 원인: 실행 방식 (n_action_steps)

**v2 데이터 결과가 오히려 나빠짐** (1/30, 28 회 출발 못 함) → "시작 정지" 가설이 틀렸을 가능성.

**오프라인 확인**: 학습 데이터의 첫 프레임(준비 자세)을 넣으면 두 정책 모두 **움직이라고 정확히 예측**했다
(30 step 뒤 예측이 준비 자세에서 크게 벗어나고 시연 값과 비슷). 학습은 잘 됐고, 문제는 실행 쪽.

**원인**: 시연 동작은 천천히 출발해 가속한다 (구간마다 부드러운 출발 곡선). 정책은 30 step 을 예측하지만 앞 10 step(0.33 s)만 실행하고 다시 예측한다.
출발 직후 10 step 동안은 거의 움직이지 않으므로 다시 예측할 때 관측이 여전히 '출발 직전' 처럼 보이고,
정책이 '출발' 을 계속 처음부터 반복한다 → 제자리에서 맴돈다. 시간에 따라 진행되는 동작을 관측만으로는 구분할 수 없어서 생기는 문제.

**확인**: 같은 체크포인트를 `--n-action-steps 30` (예측 묶음을 끝까지 실행) 으로 돌리니 v1, v2 모두 **10/10 성공**,
기준선이 실패하던 상자 위치(왼쪽 끝)도 성공. 시뮬 RTF 1.00.

**교훈**
- 닫힌 루프 실패를 데이터 탓으로 돌리기 전에, **학습 데이터 위에서 오프라인 예측**을 먼저 본다. 학습 문제인지 실행 문제인지 갈린다.
- 평가는 항상 같은 조건(RTF 1.00, 같은 시드)에서. 뷰어 + 학습 동시 실행은 RTF 를 떨어뜨려 결과를 왜곡한다.
- 다른 대응: ACT 의 temporal ensembling (`temporal_ensemble_coeff`, 매 step 예측을 겹쳐 평균) 도 같은 문제를 푼다. 이후 비교 후보.

## 7. 몸 쪽 상자 보정: 시연 개선 + 데이터 추가 + 파인튜닝

남은 실패는 모두 **상자가 몸 쪽에 가까울 때** (x ≤ 0.25, 목표 x = 0.27). 같은 시연을 더 모아도 효과가 없었으므로(50 → 100 개, 실패 동일)
시연이 x 를 보정하도록 바꿨다: 밀기 끝 x 를 `x + (target_x - box_x)` 로 옮겨 **비스듬히 민다** (`auto_push --correct-x`).

전문가(스크립트) 자체 비교 — 몸 쪽 상자 (x 0.235 ~ 0.26), 10 회씩:

| 시연 | 성공 | 목표까지 거리 |
|---|---|---|
| 기존 (y 로만 밀기) | 5/10 | 2.8 ~ 4.6 cm |
| **비스듬히 밀기 (`--correct-x`)** | **10/10** | 1.6 ~ 2.5 cm |

- v3 데이터: v2 100 개 + 몸 쪽 상자 비스듬히 밀기 40 개 (40 / 40 성공, 시드 50, `--box-x-range 0.235 0.26`) = **140 개, 21,128 프레임**
- 파인튜닝: 40k 정책에서 시작해 v3 로 10k step (`INIT_FROM=... bash training/il/train_act.sh`). 정규화 통계는 v3 로 갱신된다.
- 평가: 같은 조건 (시드 123, 30 회, n_action_steps 30)

| 정책 | 성공률 |
|---|---|
| 40k (v2 100 개) | 27/30 = 90 % |
| **40k + 파인튜닝 10k (v3 140 개)** | **30/30 = 100 %** (평균 거리 2.0 cm, RTF 0.94~1.00, 뷰어 켬) |

| 상자 위치 | 40k (v2 100 개) | 40k + 파인튜닝 (v3) |
|---|---|---|
| 몸 쪽 (x ≤ 0.26, 13 회) | 10/13, 평균 4.0 cm | **13/13, 평균 2.8 cm** |
| 나머지 (17 회) | 17/17, 평균 1.4 cm | 17/17, 평균 1.4 cm (변화 없음) |

- 몸 쪽 상자에서 비스듬히 미는 동작을 배웠고, 기존 데이터를 섞어 학습해 나머지 상자 성능은 그대로였다 (잊지 않음).
- 실패 원인이 '시연에 없던 동작' 이라는 진단을 확인: 그 동작 40 개 + 파인튜닝 25 분으로 해결.

## 참고

- 200 step 만 학습한 정책도 2/2 성공했다 → 과제가 쉬울 수 있다는 신호였고, 그래서 기준선을 만들었다.
- 추론 시간 (1060): 중앙값 4 ms. 새 행동 묶음을 예측할 때(10 step 마다) 최대 ~50 ms, 첫 호출 ~290 ms.
